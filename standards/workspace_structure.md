# Workspace Structure

Required skeleton for every course-learning guide. The fleet is all-Manning;
guides nest under topic folders (`<topic>/<slug>/`). Per-guide deviations are
documented generically in the guide's own `CLAUDE.md` and `source_manifest.md`,
not via per-family overlays.

## Required skeleton

```text
<topic>/<slug>/
├── guide/                               # LaTeX workspace (build root)
│   ├── main.tex                         # Root document (MAIN=main); builds to main.pdf / main_digital.pdf
│   ├── Makefile                         # Standard QA targets — see audit_catalog.md
│   ├── references.bib
│   ├── notebook-extensions.sty          # Per-guide LaTeX extensions
│   ├── appendices/
│   │   ├── A_quick_reference.tex        # REQUIRED
│   │   ├── B_gotchas_debugging.tex      # REQUIRED (or B_gotchas.tex)
│   │   ├── C_glossary.tex               # REQUIRED
│   │   ├── D_interview_prep.tex         # REQUIRED — see interview_standard.md
│   │   ├── E_post_course_updates.tex            # Gold G7: post-course/tooling drift (name-locked)
│   │   └── F_contrasting_opinions_open_debates.tex # Gold G7: open debates (name-locked, waiverable)
│   ├── chapters/*.tex
│   ├── cards/*.yml                      # Auto-generated by tooling.cards.extract_cards
│   └── decks/*.apkg                     # Auto-generated by tooling.anki.yaml_to_apkg
├── review/
│   ├── dashboard.md                     # Auto-generated by tooling.qa.guide_health
│   ├── source_manifest.md               # Provenance manifest (Silver-tier; aspirational today)
│   ├── interview_connections.md         # High-level interview mapping
│   └── gold_audit_*.md                  # Gold audit artifacts (per-guide; mostly auto-generated)
├── code/                                # Companion code, OR documented no-code status
├── guide_qa.yaml                        # QA config and thresholds (see audit_catalog.md)
├── notes/                               # Per-guide working notes (where present)
└── README.md
```

## Allowed source layouts

Authored chapters live in `guide/chapters/*.tex`. One documented exception
for the *source* of that content:

1. **Upstream-mirrored canonical source** (e.g., `manning_rlhf_book` mirrors
   `natolambert/rlhf-book` to `code/book/chapters/*.md`): the canonical source
   path is `code/book/chapters/`, not the guide workspace. The source manifest
   must declare this. Per-guide `CLAUDE.md` should have a "Canonical content
   source" section.

The source manifest (`review/source_manifest.md`) declares which layout a
guide uses.

## Appendix policy

- **A, B, C, D required**:
  - A: quick reference
  - B: gotchas / debugging
  - C: glossary
  - D: interview prep — see [`interview_standard.md`](interview_standard.md)
- **E, F — Gold currency appendices (G7), filename-keyed.** For **Gold**, two
  appendices are required and **name-locked** — the Gold runner matches the exact
  filenames, not the appendix slot letter (see [`tier_model.md`](tier_model.md)
  §Gold G7):
  - `E_post_course_updates.tex` — dated post-course / tooling-drift updates.
  - `F_contrasting_opinions_open_debates.tex` — open debates (waiverable via
    `gold_exceptions.debates_waiver`).
  Below Gold, an `E_*.tex` may still carry other content-justified material, but
  such a file does **not** satisfy G7. `E_code_snippets.tex` (used by
  `manning_llm_from_scratch`) is **no longer** a sanctioned post-course-updates
  E — that content moves to another slot and the guide adds the keyed
  `E_post_course_updates.tex` during its Gold wave.

A stub Appendix D fails Silver tier (per
[`tier_model.md`](tier_model.md)).

## Appendix E/F exemption

Below Gold, skip Appendix E when there are no post-course updates AND no other
content-justified material; document the absence in the source manifest. At
**Gold** there is no blanket E skip: `E_post_course_updates.tex` is required and
`F_contrasting_opinions_open_debates.tex` is required-or-waivered per
[`tier_model.md`](tier_model.md) §Gold G7.

## Companion code policy

- If the source has companion code: copy, unzip, or clone into `code/`. The
  source manifest declares the upstream URL and the local path.
- If the source has no companion code: explicitly document "no-code" status
  in the source manifest AND in `README.md`. An empty `code/` directory is
  not enough.
- Acquisition automation is a deferred follow-up; today acquisition is manual.

Companion code is acquired from the upstream GitHub repo (the fleet is
all-Manning); companion-code submodules under `<guide>/code/` are public and
pinned.

## Build root

Every guide builds to a single LaTeX root document at `guide/main.tex`
(`MAIN=main` in the guide Makefile), producing `main.pdf` (pilot) and
`main_digital.pdf` (digital).

Build is via `make -C <topic>/<slug>/guide pilot` (single-pass) or
`make -C <topic>/<slug>/guide digital` (full multi-pass with index/bib). See
[`audit_catalog.md`](audit_catalog.md) for the full Makefile target list.

## Inventory source of truth

For "is this workspace a guide?" the canonical answer is: **the slug root has
a `guide_qa.yaml` at its top level**, and `make audit-all`
(`python -m tooling.audits.fleet.audit_all_courses`) discovers it recursively.
Directory naming is a sanity check, not authoritative — some directories are
templates, archives, or partial extractions without a `guide_qa.yaml`.

Catalog precedence when sources disagree:

1. `guide_qa.yaml` discovery (the actual workspace existence test).
2. The guide registry (`guides.yml` at the guides-manning repo root) for known
   catalog metadata.
3. Latest fleet audit (`reports/inventory_and_quality.md`) for current QA
   status.
4. Directory naming only as a last-resort fallback.
