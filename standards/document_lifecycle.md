# Document Lifecycle

Policy for keeping, archiving, and deleting documentation in this repo. The
policy is operationalized once on 2026-04-19 by the standards-consolidation
PR; future enforcement is a follow-up (`tooling.audits` doc-lifecycle lint).

## Core principle

**Deletion is preferred. Git history is the archive.** No `docs/_archive/`
directory exists. If a doc is no longer current, delete it via `git rm` and
commit. Recovery uses:

```bash
git log --all --full-history -- <path>
git show <sha>:<path>
```

The single exception is files that genuinely benefit from being read by future
contributors (e.g., a one-time recalibration record that explains why current
targets are what they are). These get a top-of-file supersession banner — see
below.

## Document categories and policies

### 1. Authoritative standards

Location: `tooling/standards/` (the flat standards tree).

- Edited by humans.
- No expiry.
- Version bumps recorded in `tooling/standards/CHANGELOG.md`.

### 2. Auto-generated artifacts

Examples: per-guide `review/dashboard.md`, `readiness-*.md`, `supplement_coverage_audit.md`,
fleet `reports/qa_fleet_audit_*.md`.

- Regenerated by scripts. Tracked in git so the latest state is visible.
- **Never edited by hand.** To change them, change the script.
- Only the most recent fleet-audit file is kept; older ones `git rm`'d on each
  new run. (The audit script should be updated to do this automatically — a
  follow-up.)

### 3. Active plans

Forward work is tracked in `ROADMAP.md` at the repo root; any stream-specific
working docs live alongside it (repo root or `reports/`).

- Live working docs. One per active stream.
- When the plan's work is complete, `git rm` the plan (or fold it back into
  `ROADMAP.md`). The value lives in the resulting commits and (where
  applicable) standards-tree updates.
- Naming: `{topic}_{YYYY-MM-DD}.md` for traceability.

### 4. Frozen snapshots

Examples: one-off content censuses, target-recalibration records, manual audit
narratives.

- If not referenced by an active plan, `git rm` after 30 days.
- Do not move to an "archive" directory. The git history is sufficient.
- If kept beyond 30 days, must carry a top-of-file banner explaining why.

### 5. Per-guide `CLAUDE.md`

Location: per-workspace.

- Minimal: identity, canonical-source path, guide-specific deviations from the
  standards.
- Universal craft rules and tier definitions live in `tooling/standards/`, not
  in per-guide `CLAUDE.md`.
- Template: `tooling/standards/templates/CLAUDE.guide.md.template`.
- Migration: examples landed in the standards-consolidation PR
  (`manning_rlhf_book` and peers); remaining files are tracked by the
  remediation plan.

### 6. Per-guide `review/` audit reports

- Auto-generated when produced by an audit script: kept fresh by the script.
- Manually authored: treat as frozen snapshots (category 4) — `git rm` after
  30 days unless an active plan references them.

## Supersession markers

A superseded doc that is being kept (rare — prefer deletion) must have a
top-of-file banner:

```
> **Superseded on YYYY-MM-DD by [path/to/replacement].** This file is kept
> because [reason]. Do not consult it for current guidance.
```

Files marked superseded for >30 days are `git rm`'d.

## Archive directory policy (resolved 2026-04-19)

- **`_archived/` at repo root**: deleted in the 2026-04-19 consolidation PR.
  Contained ~2 GB of abandoned coursework + 9 gitlink-style references to
  external repos. Removed because (a) agent grepping returned irrelevant
  material; (b) git history preserves it for true emergencies.
- **Per-guide `_archive/` directories** (e.g., `manning_rlhf_book/_archive/`):
  also deleted. Were rollback snapshots; git history is the rollback
  mechanism.
- **`docs/archive/`** (different from the deleted `_archived/`): contained 2
  superseded planning docs which were also deleted in the 2026-04-19 PR. The
  empty directory was removed.

If new archive directories appear in the future, the policy is: **don't
create them**. Either delete (preferred) or carry a supersession banner.
