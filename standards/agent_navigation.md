## Navigation principles

1. **The flat standards tree wins for craft details.** If you need to know how
   a margin note works, read `content_design.md` in this directory. The fleet
   is all-Manning, so there are no per-family overlays — the standards in
   `tooling/standards/` are authoritative for every guide.
2. **Per-guide `CLAUDE.md` is for guide-specific deviations only**, not for
   restating standards. If a guide's `CLAUDE.md` contradicts the standards,
   the standards win and the `CLAUDE.md` should be migrated.
3. **Auto-generated artifacts are not edited by hand.** Per-guide
   `dashboard.md`, `readiness-*.md`, fleet `qa_fleet_audit_*.md` files are
   regenerated by scripts. To change them, change the script.
4. **When in doubt, run the audit.** `make audit-all` (which runs
   `python3 -m tooling.audits.fleet.audit_all_courses`) is the source of truth
   for current fleet state.

## What is NOT in this index

- **The cross-guide learning graph** itself (which guide leads to which). Its
  edges are the per-guide `\crossrefmargin{}` notes; the policy that governs
  them lives in `cross_references.md`. This file points you there but does not
  duplicate the graph.
- **Specific guide content.** This file is about *where standards live*, not
  *what any specific guide teaches*.
- **Implementation details of audit scripts.** Read the script source for
  that. This file points at the catalog (`audit_catalog.md`) which describes
  *what each script measures*, not *how it computes the measure*.
